# github-repo-updater
Утилита для автоматического обновления состояния репозиториев в указанной директории

В окне приложения можно выбрать директорию, найти репозитории и обновить их
кнопкой «Обновить все». Поиск рекурсивный, но не заходит внутрь найденного
репозитория: субмодули проверяются вместе с ним. Поддерживаются каталоги `.git`
и файлы `.git` у worktree. Символические ссылки при обходе пропускаются.

Поиск и обновление выполняются в отдельном потоке. Репозитории обрабатываются
последовательно; ошибка одного не останавливает остальные. Таблица показывает
статус каждого репозитория, а выбор строки открывает подробности. По окончании
цикла проблемы показываются во всплывающем окне или уведомлении трея.

Крестик окна скрывает приложение в системный трей. Щелчок по значку или пункт
«Открыть» возвращает окно; меню трея также содержит «Обновить все» и «Выход».
Полный выход доступен и через «Файл → Выход». Если обновление выполняется,
выход дожидается текущего репозитория, не начинает следующий и не прерывает Git.
Если системный трей недоступен, крестик оставляет окно видимым.

Автообновление включается отдельно, интервал — от 1 до 1440 минут. Таймер
работает и при скрытом окне; следующий интервал отсчитывается после окончания
предыдущего цикла. Директория, интервал, переключатель автообновления и геометрия
окна сохраняются через QSettings. При запуске обновление немедленно не выполняется.
Автозапуск приложения вместе с Windows пока не настраивается.

Слой Git состоит из `GitRunner` (запуск команды) и синхронного
`RepoUpdater::update(path)` для одного репозитория.

Обновление проверяет локальные изменения, незавершённые операции Git, индекс,
существующие субмодули рекурсивно и upstream текущей ветки. Затем выполняет
`fetch` только в remote-tracking ref и проверяет возможность fast-forward.
Перед применением повторно проверяет локальное состояние и текущую ветку.
Fast-forward выполняется без merge-коммита, autostash, хуков и переключения
субмодулей; перезапись игнорируемых файлов запрещена.

Локальные изменения, расхождение ветвей, локальные коммиты сверх upstream,
detached HEAD и неоднозначные состояния приводят к пропуску обновления.
Входящие изменения `.gitmodules` или указателей субмодулей пока также требуют
ручного обновления: основной репозиторий остаётся на прежнем коммите.
`fetch` может обновить объекты и remote-tracking ref даже при последующем пропуске.

После ошибки или таймаута изменения автоматически не откатываются и команда
не повторяется: состояние нужно проверить вручную. Проверки не обеспечивают
транзакцию между несколькими процессами; параллельная запись в тот же репозиторий
другими программами не поддерживается.

Сборка и тесты (Qt 6, CMake, Git доступны в окружении):

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Тесты создают локальные временные репозитории и bare remote; пользовательские
репозитории и сетевые remote не обновляются.
